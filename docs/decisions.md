# 设计与工程判断

## 产品与真实性

自创 Luma AI 概念品牌，避免复制真实产品或引用失效套餐。Hero 与演示显示概念性质，评价标为虚构，图表说明估算来源，价格标为示例。没有将示例评价写入 aggregateRating，也没有虚假公司 Logo 背书。

## 内容组织

阅读顺序：定位 → 能力 → 具体场景 → 特性 → 操作流程 → 对比 → 示例评价 → 价格 → 问答 → 行动。24 个场景默认可读，分类用于快速查找。每个场景给出输入与输出，所有重要成果需人工核实。

## 页面视觉

深色工作台、紫色强调色与局部低饱和功能色。首屏光晕、网格和渐变标题建立识别度。界面示意、卡片、步骤图和表格交替使用。移动端将侧栏转为类别按钮；窄屏卡片变为单列，图表用自适应 viewBox。

## 技术与性能

采用 Next.js App Router 静态生成两种语言。客户端边界仅覆盖交互组件。Tailwind CSS 构建流程配合自定义变量与语义类，减少长篇内联 class 的维护负担。Lucide 替代手工不一致的图标。

选择 CSS 渐变背景，而不引入 Three.js；SVG 图表，而不引入 Recharts；系统字体，而不下载外部字体。没有为加分项损害首屏网络与主线程。

## 语言与主题

语言由 URL 决定，Cookie 仅影响根入口重定向。刷新保留当前路由。主题由 HTML data-theme 与 CSS 变量控制，短小的头部脚本恢复偏好，避免明显闪烁。主题图标通过 CSS 显示，消除 effect 中同步更新状态。

## 有效交互

CTA 滚动到可操作演示或场景库。价格按钮打开原生 dialog，提供真实说明和演示入口。演示不会承诺自由输入触发真实推理；明确显示类别预设结果。复制失败提供手动选择提示。

## 无障碍

原生 FAQ details/summary、原生模态 dialog、语义化 table、图表 title/desc、可见焦点和跳转主内容。根据 Lighthouse 补充演示 H2，以保证 H1 → H2 → H3 层级；品牌直接使用可见文本作为名称。减少动画偏好下无滚动动画。

## AI 与验证边界

Codex 辅助起草与实现。最终取舍围绕实际可运行结果，构建、类型检查、ESLint、Playwright 和 Lighthouse 作为证据。不把模拟数据当测试数据，不把本地性能当作线上性能。

## 完整主题对比度检查

Lighthouse 首测未报告卡片序号的对比度问题。额外在减少动画模式下让全部区块可见，再使用 Axe 扫描深色、浅色和打开的方案弹窗。发现卡片序号的 opacity 以及浅色标签/头像颜色问题，并调整为可读的前景色。记录自动化检查结果，不把分数等同于完整 WCAG 认证。
